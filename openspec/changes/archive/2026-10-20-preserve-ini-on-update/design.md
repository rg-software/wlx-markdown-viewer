# Design

## Context

See `proposal.md` for motivation. The plugin stores its settings in `MarkdownView.ini` next to the DLL. `InitOptions()` in `HTMLView/functions.cpp` assumes the file exists and warns the user if it does not. The release package currently includes `MarkdownView.ini`, so Total Commander's auto-installer overwrites user changes on update.

## Goals / Non-Goals

**Goals:**
- Prevent update installs from clobbering an existing `MarkdownView.ini`.
- Ensure a usable default configuration on first run.

**Non-Goals:**
- Migrating or versioning INI schemas.
- Changing how settings are read elsewhere in the codebase.

## Decisions

1. **Rename shipped default to a template**
   - Use `Build/MarkdownView.ini` as the template source but ship it as `MarkdownView.ini.sample` in the archive.
   - Rationale: Total Commander's documented guidance is to avoid shipping a live `.ini`; a `.sample` file is ignored by the installer's overwrite concern and by `GetPrivateProfile*` (which only reads `.ini`).
   - Alternative: remove the INI from the archive entirely and embed defaults in code. Rejected because the INI is large and user-editable; a template keeps customization discoverable.

2. **Create default INI at startup**
   - In `InitOptions()`, if `MarkdownView.ini` does not exist, copy `MarkdownView.ini.sample` (same directory) to `MarkdownView.ini` before reading settings. If the sample is also missing, keep the current behavior of warning the user.
   - Rationale: keeps the existing read path unchanged and only adds creation logic.
   - Alternative: read from the sample directly when INI is missing. Rejected because later writes (e.g. log settings) expect the `.ini` path.

3. **Packaging**
   - `BuildMakeSetup.bat` and `.github/workflows/release.yml` copy `Build\*.ini.sample` (or explicitly `MarkdownView.ini.sample`) instead of `Build\*.ini`.
   - Keep `Build/MarkdownView.ini` in source as the template; rename only at packaging time, or rename in source and update references. Renaming at packaging keeps source paths stable.

## Risks / Trade-offs

- [Existing installs] Users who already lost settings cannot be restored automatically; only future updates are protected.
- [Template drift] If `Build/MarkdownView.ini` changes, the sample must be regenerated by the build. Mitigated by deriving the sample from the same file.
- [First-run copy failure] If the plugin directory is read-only, creation fails; the existing warning path covers this.

## Migration Plan

1. Update packaging to ship `MarkdownView.ini.sample`.
2. Update `InitOptions()` to copy the sample when `.ini` is missing.
3. Rebuild and verify first-run creation and update preservation manually.
